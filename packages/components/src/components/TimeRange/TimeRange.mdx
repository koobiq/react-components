# TimeRange

<Status variant="experimental" />

`TimeRange` is a popover-based time range picker: a trigger showing the selected
period, relative-time presets ("last 7 days", "current quarter", …), and a
manual from/to editor for custom ranges. Changes in the editor only take effect
when Apply is pressed; Cancel discards them.

## Import

```tsx
import { TimeRange } from '@koobiq/react-components';
```

## Custom trigger

Render a `TimeRange.Trigger` as `TimeRange`'s child to replace the default
trigger entirely. Its function child receives the formatted value, the
popover's open state, and `buttonProps` — spread `buttonProps` onto whatever
pressable element you render so it gets the popover's press/keyboard/ref
wiring.

<Story of={Stories.CustomTrigger} />

## Trigger as a form field

Build a custom `Select`-like control by rendering a `FormField` inside
`TimeRange.Trigger`'s render function — its `isDisabled`/`isEmpty` state
mirrors onto `FormField`/`FormField.ControlGroup` so the field's chrome
(background, border) reacts the same way a built-in `FormField` control does.
Use the unstyled `Button` primitive from `@koobiq/react-primitives` for the
pressable element so it doesn't paint its own border on top of
`FormField.ControlGroup`'s, and forward `FormField.ControlGroup`'s own
`onMouseDown` to the trigger (see the story's source) so clicking anywhere in
the field — not just the button — opens the popover.

## Custom presets

`customTimeRangeTypes` registers additional presets beyond the built-in
`TimeRangeType`s. Each needs a `units` duration (used to compute the range
relative to "now") and a `translationType`, used to pick the unit word when
formatting the label.

<Story of={Stories.CustomRangeTypes} />

## Custom preset ranges

A custom preset's `range` overrides the "now minus units" computation with a
fixed `start`/`end`, useful for calendar-anchored presets like fiscal quarters.
`renderOption` customizes how each preset is labeled in the editor.

<Story of={Stories.CustomOption} />

## Correcting out-of-range values

When a `value`/`defaultValue` (or `customTimeRangeTypes`/`availableTimeRangeTypes`
change makes the current value's type unavailable), `TimeRange` falls back to
the first available preset and calls `onValueCorrected` with the corrected
value. For an uncontrolled `defaultValue`, `TimeRange` also applies the
correction to its own state. For a controlled `value`, it never fires
`onChange` on your behalf — apply the correction to your own state in the
`onValueCorrected` handler if you want it reflected.

## Utilities

`TimeRange`'s preset and validation logic is exposed as pure functions, useful
for replicating the same computation or formatting outside the component (for
example, to build an API query for the currently selected range).

- **`calculateTimeRange(type, customTimeRangeTypes?, manualRange?)`** — resolves a
  preset's absolute `start`/`end` bounds. Duration-based presets are computed
  relative to now; `range` (and any custom preset with a fixed `range`) passes
  its bounds through.
- **`formatTimeRangeDuration(type, entry, t, range?, formatter?)`** — formats a
  preset's label ("Last 7 days", "Current quarter", …) for display outside the
  component's own trigger/editor, given the entry looked up via
  `getTimeRangeTypeConfig(type, customTimeRangeTypes?)` and a
  `LocalizedStringFormatter`. For `type: 'range'`, pass the
  resolved `start`/`end` bounds and a `DateFormatter` (e.g. from
  `useDateFormatter({ month: 'long', day: 'numeric' })`) to get the actual
  span ("August 31 – September 1") instead of the literal "Custom range"
  fallback.
- **`getTimeRangeTypeConfig(type, customTimeRangeTypes?)`** — looks up a
  preset's `entry` (its `units`/`translationType`), checking the built-in
  presets first and falling back to `customTimeRangeTypes`; the input
  `formatTimeRangeDuration` expects for its `entry` argument.
- **`combineDateTime(date, time)`** / **`splitDateTime(dateTime)`** — combine or
  split a date and a time-of-day, the same operation the manual editor uses to
  turn its two fields into one comparable value.
- **`isRangeValid(start, end)`** — checks that a manual range's `start` is not
  later than its `end`; use it to validate a `TimeRangeInstant` pair before
  submitting a form.
- **`getDefaultRangeValue(minValue?, maxValue?)`** — "yesterday → today",
  clamped to the given bounds; the default seed for a manual range editor.
- **`checkAndCorrectTimeRangeValue(value, availableTimeRangeTypes, customTimeRangeTypes?, minValue?, maxValue?)`**
  — the standalone version of the correction `TimeRange` runs internally;
  useful for validating a value before setting it as a controlled `value` prop.

## Accessibility

The trigger exposes `aria-haspopup`/`aria-expanded`. The editor is rendered in
a `role="dialog"` popover; presets are a standard `RadioGroup` supporting
arrow-key navigation, and the manual from/to fields reuse `DatePicker`'s and
`TimePicker`'s existing keyboard support.
