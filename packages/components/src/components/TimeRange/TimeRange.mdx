# TimeRange

<Status variant="experimental" />

`TimeRange` is a popover-based time range picker: a trigger showing the selected
period, relative-time presets ("last 7 days", "current quarter", …), and a
manual from/to editor for custom ranges. Changes in the editor only take effect
when Apply is pressed; Cancel discards them.

## Import

```tsx
import { TimeRange } from '@koobiq/react-components';
```

## Form field

Like `Input`, `Select`, and `TreeSelect`, `TimeRange`'s default trigger is a
`FormField` control: pass `label`, `isLabelHidden`, `isRequired`, `caption`,
`isInvalid`, `errorMessage`, `fullWidth`, `labelPlacement`, and `labelAlign`
directly, the same as any other form field. Reach the underlying `FormField`
parts via `slotProps.root`/`.label`/`.group`/`.caption`/`.errorMessage` for
anything not covered by a dedicated prop.

<Story of={Stories.Invalid} />

## Custom trigger

Render a `TimeRange.Trigger` as `TimeRange`'s child to replace the default
trigger entirely — this opts out of the built-in `FormField` wiring above, so
`label`/`caption`/`isInvalid`/`errorMessage` have no effect. Its function
child receives the formatted value, the popover's open state, and
`buttonProps` — spread `buttonProps` onto whatever pressable element you
render so it gets the popover's press/keyboard/ref wiring.

## Custom presets

`customTimeRangeTypes` registers additional presets beyond the built-in
`TimeRangeType`s. Each needs a `units` duration (used to compute the range
relative to "now") and a `translationType`, used to pick the unit word when
formatting the label.

<Story of={Stories.CustomRangeTypes} />

## Custom preset ranges

A custom preset's `range` overrides the "now minus units" computation with a
fixed `start`/`end`, useful for calendar-anchored presets like fiscal quarters.
`renderOption` customizes how each preset is labeled in the editor.

<Story of={Stories.CustomOption} />

## Correcting out-of-range values

When a `value`/`defaultValue` (or a `customTimeRangeTypes`/
`availableTimeRangeTypes` change) makes the current value's type unavailable
— or an available `'range'` value is missing `start`/`end` — `TimeRange`
falls back to the first available preset (recalculating `start`/`end` for
`'range'` when needed) and reflects the correction immediately, for both
controlled and uncontrolled values. For an uncontrolled `defaultValue`, the
correction is also applied to the component's own state. For a controlled
`value`, it's only reflected in what's rendered — `TimeRange` never rewrites
your prop — so update your own state in the `onValueCorrected` handler if
you want the next render's `value` to agree with what's already shown.

## Accessibility

The trigger exposes `aria-haspopup`/`aria-expanded`. The editor is rendered in
a `role="dialog"` popover; presets are a standard `RadioGroup` supporting
arrow-key navigation, and the manual from/to fields reuse `DatePicker`'s and
`TimePicker`'s existing keyboard support.
